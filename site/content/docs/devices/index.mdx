Every device renders at the exact pixel size the store accepts, as an opaque PNG. **Settings**
lists them grouped as Apple names them; tick the ones the app needs. Import App proposes a set
from the app itself: landscape sets for an app that only runs sideways, iPad only if it runs on
iPad, Google Play only when `fastlane/metadata/android` exists.

## What the App Store requires

- **iPhone 6.1"** is the size Apple names as required. Without it Apple scales the 6.9" set down,
  so the tool warns rather than fails. It renders from the same captures as 6.9"; add it.
- **iPad 13"** is required for an app that runs on iPad.
- **iPhone Duo** sets are required from April 2027. See [iPhone Duo](/docs/devices/duo).

[Ship's checks](/docs/ship) report a missing required set before anything uploads.

## One capture, many sizes

Captures belong to a device family, not a size: one iPhone capture serves 6.9", 6.1", the
header and search images, iPhone Duo and event media. An iPad capture serves iPad 13". Positions
are fractions of the screen, so a layout made at 6.9" lands in the same place at 6.1"; devices
with a different shape (iPad, landscape) usually want their own positions.

## Pictures that are not screenshots

The header and search images, the event media and the Google Play feature graphic are not part of
the screenshot strip. A screen makes them only when its **Devices** list names them (the
**Screen** tab in Design), and such a screen takes no screenshot position.
